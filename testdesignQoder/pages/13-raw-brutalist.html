An agent that reads the repository before it writes a single line.

This document describes what Agent 01 does, what it refuses to do, and how to run it on your own machine. It is short on purpose. Nothing here is a metaphor.

01

Scope

defines the boundary of the system; anything outside this line is somebody else's problem

Agent 01 is a program that runs on your machine, in a terminal or an editor, and works on a directory of source code that you hand it. It reads files. It forms a plan. It proposes edits as diffs. It stops.

It is not a chat window with a text field bolted to a codebase. There is no cloud workspace, no hosted index of your private code, and no background process that keeps running after you close the window.

What it is not

  • A search engine. It uses one (§04) but answers with edits, not links.
  • An autocomplete. Suggestions arrive as reviewable patches, never as keystrokes inserted under your fingers.
  • Autonomous. Every write is gated on an explicit approval, per file, per hunk.
02

Method

four steps, strictly ordered; the agent cannot enter a later step without evidence from the earlier one

  1. Read. The agent walks the tree, resolves imports, and reads every file it intends to touch, in full — not a window around the target line. evidence required: complete file contents, recorded in the run log
  2. Plan. It writes a numbered plan of edits in plain language, each tied to a file and a reason. evidence required: at least one plan item, or the run fails as “no change proposed”
  3. Edit. It produces unified diffs, one per file. Nothing is written to disk before you approve. evidence required: a diff that applies cleanly to the revision it read
  4. Verify. It runs the project's own tests and type checks, then reports pass, fail, or inconclusive. evidence required: exit codes, kept in the log whether they flatter the agent or not

The run log is a file you own: ./agent01/runs/<timestamp>.jsonl. Every read, plan item, diff and test result is a line in it. Delete it whenever you like; nothing else depends on it.

aside — steps 1 and 4 account for roughly 80% of wall-clock time, and all of the trust

§03  ·  the one claim worth colouring

It will not write to a file it has not read in full.

Every other capability on this page is a convenience. This one is the product. An agent that edits code it has not read is guessing with your repository, and a guess that compiles is still a guess.

Enforced in the writer, not in the prompt: the edit call takes a content hash of the file as read. If the hash does not match the bytes on disk at write time, the write is refused. See §05 for the refusal rate, which is 0.00% on unchanged trees and 100% on hand-edited ones.

04

Capabilities

what the agent can do today, with the command that proves it

  • Whole-tree reading. Follows imports and re-exports to the files that actually matter. agent01 read
  • Planned refactors. Renames a symbol across a module in one reviewed pass, ordering the edits so the tree is never left inconsistent between hunks. agent01 plan --rename
  • Test-aware fixes. Reads the failing test first, then the code under it. agent01 fix --test
  • Migration drafting. Rewrites call sites against a new interface and reports the ones it could not resolve instead of inventing arguments. agent01 migrate
  • Explained diffs. Every hunk carries a one-line reason you can reject on its own. agent01 diff --explain

Interfaces

Terminal, VS Code extension, and a small HTTP API on 127.0.0.1 that the other two are built on. Press ⌘K in the editor build to open the plan list; Esc always aborts a run, and an abort leaves the tree exactly as it found it.

06

Limits & access

known failures, stated plainly, because a feature list without them is advertising

  • Repositories above roughly 2 GB of text will exhaust the default context budget. Raise it with --budget, and expect a slower plan.
  • Generated code is read but not planned against. Exclude it with .agent01ignore.
  • The agent does not run migrations against a live database. It writes the migration; running it is yours.
  • Monorepos with more than one package manager are supported badly. We know. It is the next release.

Install: curl -fsSL agent01.dev/install | sh, or read the source first, which we would prefer. Binaries for macOS, Linux and Windows. No account, no telemetry endpoint.

Questions and bug reports go to mail@agent01.dev or the issue tracker. We answer within two working days, and we publish the fix in the log before we announce it.

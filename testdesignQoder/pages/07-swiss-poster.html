Meridian

An autonomous agent for engineering teams. It reads the repository, plans in the open, runs its own code in a sealed sandbox, and hands back a pull request with the reasoning attached.

01

Premise

It does the work, not the talking

Most assistants stop at a suggestion. Meridian opens the file, changes it, runs the suite, and reports what broke. You review a diff, not a paragraph.

Everything it did is stored beside the change: which files it read, which commands it ran, what came back.

Perceive / plan / act

02

Method

Four moves, always in this order

  1. 1.

    Read

    The whole tree, ranked by relevance. Nothing is edited before it is understood.
  2. 2.

    Plan

    A numbered plan, written before the first edit and shown to you.
  3. 3.

    Execute

    Edits and commands, each one reversible and each one logged.
  4. 4.

    Report

    A diff, the test output, and the two decisions worth questioning.

04

Instruments

Nine tools, no shell escape

Every tool declares a capability set. The agent can never exceed the intersection of the tool scope and your role.

  1. A

    read_file / read

    Path-scoped, 400 ms median
  2. B

    apply_patch / write

    Unified diff, atomic per file
  3. C

    run_process / sealed

    No network, 90 s wall clock
  4. D

    search_index / read

    Hybrid lexical and vector

05  Guardrails

Guardrails

Nothing leaves the sandbox without a signature.

Escalation

Writes outside the working tree, credential reads and any network egress stop the run and ask.

Reversibility

Every run is a branch. Discarding it is one command and leaves no residue.

Records

Append-only log, exportable as JSON or as a signed transcript.

07

Handoff

The thread outlives the session

A run belongs to the repository, not to a laptop. Hand it to a colleague and they inherit the plan, the sandbox and the reasoning, then continue in the same thread.

Two engineers may read one thread at once. Only one may act on it.

Reading order

  1. aDiff
  2. bTool calls
  3. cTest output

08

Start

Three lines to a branch

Install the runner, point it at a repository, open a thread. The first run indexes the tree and stops there.

Reference  /  v2.4.1

→ npm i -g meridian-runner

→ meridian init --repo ./atlas-web

→ meridian thread open --plan

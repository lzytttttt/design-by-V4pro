01—

What the runtime promises

An agent is a program that runs against a world that keeps failing. Vendors time out, tools return half-filled objects, and a queue that behaved for six weeks starts behaving badly at 02:14 on a Tuesday. Our runtime does exactly one unusual thing: it treats failure as the normal case and budgets for it explicitly.

Every turn gets a retry budget, measured in tokens rather than attempts, so a slow vendor cannot quietly spend the whole request. Once the budget is gone the turn degrades on purpose — it returns the partial answer plus a note explaining what it could not reach. Budget.exhausted is a return value, not an exception.

The rest of this notebook is the evidence. Cell 1 surveys the corpus, cell 2 draws the latency distribution, cell 3 shows the diff we shipped on Friday.

02—

Ingest, dedupe, resolve ~2.4s

Everything starts with the feed. It is not clean: roughly one event in sixty arrives malformed, and about seven per cent are duplicates that a naive reader will happily count twice. The dedupe window is deliberately short — ninety seconds — because longer windows erase genuine retries from the record.

Tool resolution is the expensive part, so it is cached per trace. The cell below runs against a frozen slice of Q1 traffic; on your machine it will run against a CSV in the same shape.

03—

Where the latency actually goes one afternoon

Mean latency is a lie told by a comfortable average. The distribution is what you feel, so the cell plots the whole shape: eleven buckets, six hours of production traffic, no smoothing.

The interesting part is the right shoulder. Everything past 900 milliseconds is a cold start on the pricing service, and it accounts for a third of all user-visible slowness while being almost invisible in the mean.

04—

What changed on Friday v0.9.4

One change mattered: attempts became tokens. A vendor that answers slowly now spends more of its budget than one that fails fast, which is precisely the behaviour we want and precisely what the old counter could not express.

The diff is small. Most of the work was in making the failure path observable, which is the sort of thing that never looks impressive in a changelog.
